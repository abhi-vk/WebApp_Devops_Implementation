⌘FOUNDATIONS

Git & collaboration

A reliable history for every change.

What

Git records changes as commits; GitHub hosts repositories and supports team collaboration.

Why

Review changes, work on branches, and keep a traceable source of truth for your project.

Try it

Create a branch, commit a small change, open a pull request, and merge it.

Git official tutorial ↗
⚡BUILD & SHIP

CI/CD & GitHub Actions

Automate the boring, catch issues early.

What

CI runs integration and checks frequently; CD automates the path to releasing software. Actions runs repository workflows.

Why

Small changes and automated checks give fast feedback and make releases repeatable.

Try it

Run your Python tests on every pull request, then add a separate deployment workflow.

GitHub Actions docs ↗
🐳BUILD & SHIP

Docker & containers

Package your app and its runtime together.

What

A container image packages an application and the pieces it needs; a container is a running instance.

Why

Consistent images help reduce differences between a laptop, CI runner, and production.

Try it

Containerize this Flask app, run its health check, then use a multi-stage build to slim the final image.

Docker multi-stage builds ↗
☸PLATFORM

Kubernetes fundamentals

Describe the desired state; let the platform reconcile it.

What

Kubernetes orchestrates containerized workloads. Deployments manage replicas; Services provide stable network access.

Why

It helps manage rollouts, recovery, scaling, and service discovery across a cluster.

Try it

Apply a Deployment and Service manifest, then inspect them with kubectl get and kubectl describe.

Kubernetes concepts ↗
⌘PLATFORM

Infrastructure & clusters

Build the foundation your workloads run on.

What

A Kubernetes cluster has a control plane and worker nodes. Managed services or self-managed setups provide that cluster.

Why

Choosing a local, managed-cloud, or self-managed cluster changes the cost and operations you own.

Try it

Start locally to learn kubectl; next, provision a small test environment with infrastructure as code.

Kubernetes cluster planning ↗ Terraform tutorials ↗
⎈PLATFORM

Helm & environments

Package Kubernetes resources as reusable charts.

What

A chart groups Kubernetes resources and configurable values into a versioned package; a release is an installed chart.

Why

Reuse one application chart while supplying different values for development, staging, and production.

Try it

Template your app's Deployment and Service, then render the chart with development and production values.

Helm guide ↗
◉BUILD & SHIP

GitOps & Argo CD

Let Git describe what should be running.

What

Argo CD is a declarative delivery tool that compares Git's desired configuration with live Kubernetes state.

Why

Git-backed changes are reviewable and auditable; drift between desired and live state is visible.

Try it

Point an Argo CD application at a demo config repo and watch it sync to a test cluster.

Argo CD documentation ↗
⇄PLATFORM

Ingress & traffic routing

Give outside traffic a route into your app.

What

An Ingress describes HTTP(S) routing rules; an Ingress controller implements them. A controller is required for Ingress to work.

Why

Route hostnames and URL paths to cluster Services and commonly terminate TLS at the edge.

Try it

Expose a test app through a controller. Note: Kubernetes Ingress is frozen; review Gateway API for new designs.

Kubernetes Ingress & Gateway note ↗
◎OPERATE

DNS & your domain

Make a friendly name find your application.

What

DNS translates domain names into records that direct clients toward the right network destination.

Why

A domain gives users a stable, memorable address even when infrastructure changes behind it.

Try it

Map a test subdomain to your ingress endpoint with the appropriate DNS record; allow time for propagation.

Cloudflare DNS docs ↗
◉OPERATE

Monitoring & observability

Understand what your system is telling you.

What

Metrics, logs, and traces offer complementary signals; Prometheus collects and stores time-series metrics.

Why

Useful signals help you spot failures, understand impact, and decide whether a change improved reliability.

Try it

Collect app and cluster metrics, create one useful alert, and practice tracing a simple failure.

Prometheus overview ↗
⬡OPERATE

Security & safe delivery

Build security into the workflow, not on at the end.

What

Protect credentials, limit permissions, scan dependencies and images, and keep deployment access controlled.

Why

Automation is powerful; least privilege and careful secret handling help reduce the blast radius of mistakes.

Try it

Use a GitHub Actions secret instead of a hard-coded token, and grant the workflow only the permissions it needs.

GitHub Actions security ↗
↗BUILD & SHIP

Put it all together

Turn the pieces into one demonstrable delivery flow.

What

A pipeline connects code review, tests, image creation, deployment configuration, rollout, and verification.

Why

Seeing the full path makes hand-offs and failure points clear; automate one step at a time.

Try it

Open a PR → test → build and tag an image → update Git → sync with Argo CD → check health and metrics.
